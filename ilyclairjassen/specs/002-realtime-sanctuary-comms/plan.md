# Implementation Plan: Realtime Sanctuary Communications

**Branch**: `002-realtime-sanctuary-comms` | **Date**: 2026-04-17 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `specs/002-realtime-sanctuary-comms/spec.md`

## Summary

Add realtime, persisted **Chat**, **Diary**, and **Memory Gallery** features to the Eternal Sanctuary. All three features sync instantly between Khent and Clair Jassen via Supabase Realtime subscriptions, with a 30-second polling fallback per the project constitution. The old `diary-panel.js` stub is removed and replaced by three independent vertical-slice feature modules. A new shared `realtime.js` helper abstracts the subscription + fallback pattern.

---

## Technical Context

**Language/Version**: Vanilla JavaScript (ES2022 modules), Vite 5  
**Primary Dependencies**: `@supabase/supabase-js` v2 (existing), Vite v5 (existing)  
**Storage**: Supabase PostgreSQL (`messages` new table; `diary`, `memories` existing tables) + Supabase Storage (`garden-images` bucket)  
**Testing**: Manual two-tab browser testing (per quickstart.md); no automated test framework in scope  
**Target Platform**: Modern mobile + desktop browsers (Chrome, Safari, Firefox)  
**Performance Goals**: Message delivery ≤ 2s; memory gallery load ≤ 3s for images < 5 MB  
**Constraints**: Image upload ≤ 10 MB; text-only chat (v1); no read receipts; write-once diary  
**Scale/Scope**: 2 users, 3 tables, 3 new feature modules + 1 shared helper

## Phase 0: Research ✅ Complete

See [research.md](./research.md).

All unknowns resolved:
- Realtime pattern: `supabase.channel().on('postgres_changes').subscribe()`
- Polling fallback: `setInterval` at 30s, activated on `CHANNEL_ERROR` / `TIMED_OUT`
- DB schema: `messages` (new), `diary.added_by` (add column), `memories` (existing — compatible)
- Notification badge: local `sessionStorage['last_chat_open']` timestamp comparison
- Reconnect: retry after 3s × 3 attempts, then fall back to polling

## Phase 1: Design ✅ Complete

### Data Model
See [data-model.md](./data-model.md).

Key decisions:
- `messages`: new table, insert-only, `sender` + `content` + `created_at`
- `diary`: existing table, add `added_by` column, write-once enforced at application layer
- `memories`: existing table, fully compatible, no schema changes needed

### Module Contracts
See [contracts/module-contracts.md](./contracts/module-contracts.md).

Key APIs:
- `initChat(user)` — chat feature entry point
- `initDiary(user)` — diary feature entry point (replaces old no-arg stub)
- `initMemories(user)` — memories feature entry point
- `subscribeWithFallback(channelName, table, onInsert, fetchAll)` — shared realtime helper

### Quickstart
See [quickstart.md](./quickstart.md).

3 Supabase dashboard steps required before feature works:
1. Create `messages` table
2. Add `added_by` to `diary`
3. Enable Realtime on all 3 tables
